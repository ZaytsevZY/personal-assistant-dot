# 每周开源调研与改进建议

先从最近已授权的任务缺口与失败出发，再考察新的开源项目或现有项目更新。优先阅读官方仓库、发行说明、许可证、安全公告和技术文档，记录当次查阅时间与实际版本。不要把旧信息当作本周更新，也不要只按星标排行。

至多提出少量值得进一步验证的候选，说明解决什么问题、与现状相比的收益、维护状态、权限和数据外发、运行成本、许可证、迁移成本及退出方案。技术结论用一手材料支持；没有实际测试就明确标为待验证，不比较虚构性能。

使用 `templates/change-proposal.md` 提出下一步最小试验和回滚方案。可以结论为“本周不改”。不安装项目、不运行远程脚本、不扩大权限、不创建调度、不发消息、不提交或推送。私人依据不写进公共材料；公开提案从合成案例重新编写。
