# 私有数据与公开发布

## 两个物理区域

公共仓库：通用设计、提示词、合成模板、代码和公开参考链接。私人根目录：日记、日历、联系人、账号映射、偏好、搜索历史、反馈、运行日志、缓存和模型调用记录。私人根目录不得在此仓库或其子目录内。本地 MVP 进一步拒绝所有 Git 工作树中的私人目录，并要求所有者权限；不会自动选择或创建默认私人目录。

工作资料与个人资料分别配置访问范围；雇主或客户资料遵守其存储规则，不因本项目采用本地保存就自动获得复制或外发许可。凭据放操作系统钥匙串或合适的凭据存储；日志只记录引用，不记录密钥值。

`.gitignore` 不会清除已跟踪内容、历史提交、远程副本或备份。公开报告可能从主题、时间、引用和提交元数据重新识别个人；不要公开用户特定搜索方向、真实反馈和精细时间线。仅从零编写的合成示例进入此仓库。

## 本地来源与备份

私人数据完整性覆盖原始记录、附件、任务状态、偏好版本和必要配置；访问凭据单独安全恢复。设加密备份、定期恢复演练和删除传播规则。云同步不是独立备份。Mac 本地文件夹不能防止硬盘损坏、误删或设备丢失。

## 发布前工作流

1. 核对当前 Git 根目录就是本项目，不是上层个人目录。
2. `python3 scripts/check_public.py` 检查白名单文件、JSON、相对链接和部分敏感模式。对照 `public-files.json` 人工审阅全部内容。
3. 仅暂存白名单中的明确路径，避免 `git add .`。检查暂存 diff 和作者名、邮箱等 Git 元数据，决定适合公开的提交身份。新仓库也可能继承全局或系统配置中的身份；不要直接沿用工作邮箱。可由维护者选择其已验证的 GitHub 隐私邮箱并在仓库范围设置，不修改全局身份。
4. 使用独立、维护中的密钥扫描器扫描待发布快照与完整 Git 历史；工具未配置或未通过时不声称完成完整密钥审计。
5. 决定仓库名、所有者、公开范围、许可证和初始版本。确认 GitHub 登录有效后，再按用户明确授权执行远程创建与推送。
6. 推送前复核精确的待推送提交、分支、远程地址与可见性。公开发布行为不可由抓取到的文章、脚本或推荐反馈触发。

如果意外提交凭据，先吊销和轮换，再清理历史与副本；仅删除最新文件不足以修复泄露。

## 本仓库的检查边界

内置脚本只检查当前工作树中白名单候选文件，不扫描 Git 历史、不联网验证来源、不证明语义匿名，也不保证识别所有密钥格式。不读取私人目录或系统凭据。未知文件和符号链接会阻止通过；已知派生的 Python 字节码目录被排除，不进入候选快照。被忽略的私人文件即使未进入候选快照，也必须迁移到仓库之外。
