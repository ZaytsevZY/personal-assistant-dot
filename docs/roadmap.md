# 阶段与验收

## 功能清单与管理入口

这张表记录随仓库发布的能力、可选运行方式与验收边界。某台设备的部署、开关或第一次送达情况由其私有运行记录确认，不能用 README 替代。

| 功能 | 仓库提供 | 部署与验证 |
| --- | --- | --- |
| 每日新闻 | 固定公开 RSS、私有按日存档、同日去重、工作台查看。见[调度设计](scheduling.md#每日新闻本机执行) | 采集与聊天投递分开配置；投递可以读取当日存档，不能把旧新闻当今天。核验两段各自的实际运行结果。 |
| 简报与推荐 | [简报说明](../prompts/news-brief.md)与[推荐政策](recommendations.md)：公共重要性、用户明确偏好与探索并存 | 私有配置控制篇幅、主题偏好和链接密度；简报应不点链接也能读懂。不把没有点击或沉默当负反馈。 |
| Apple 日历 | 经本机应用授权的有界只读，见[真实连接](real-connections.md) | 目标日历由私有配置明确选择，验证确实可读才接入复盘；仓库不包含写入实现。 |
| 每周开源调研与复盘 | [调研流程](../prompts/open-source-review.md)及[复盘流程](../prompts/weekly-review.md) | 可由选定的助手执行和投递；真实周期、来源范围和首次运行结果由该部署确认。不会自动安装候选、写入日历或公开发布。 |
| 本机项目笔记与工作台 | [本地命令](local-mvp.md)和[交互工作台](local-console.md)，支持笔记收集、状态快照、手动候选与合成演示 | 笔记通过命令收集；工作台仅本机访问，开关与后台采集分开。合成演示不是正式定时任务。 |
| 主动提醒 | [主动程度原则](charter.md#主动程度) | 计划、已授权、已启用分别记录。根据可行动性、是否有新进展、是否重复判断；频率、安静时段和停用方式由部署的用户选择。 |
| 可替换对话入口 | [入口与可移植契约](interfaces.md) | 单个聊天平台的收发测试不代表已接入同一个助手的自由对话；未验证端到端就不标记可用。 |

### 维护顺序

1. 修改通用功能、默认值或数据契约时，同步更新本表及相关测试；不得把具体用户的时刻、偏好、笔记、日历、账号或会话标识放进公开仓库。
2. 调整部署时，修改真正生效的设置而不是只改描述：采集看本机项目配置和结果，发送看已选渠道和调度，简报样式看私有偏好。
3. 区分「只有方案」「已实现还没启用」「已启用待首次验收」「已验证」。至少记下验证时间、预期、实际结果和回退方式；不把一次手动测试当作持续自动化已验收。
4. 先按任务粒度暂停或恢复，保留历史存档；仅在用户要求后改渠道、扩大范围或发布公共变更。

## 分阶段实现

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 0 手工试用 | 日常收集、新闻简报、每周发现 | 用户判断是否省时；记录错误与缺失 |
| 1 私人存储 | 仓库外资料、版本、备份与恢复 | 重建索引后原文不丢；恢复演练成功；状态不只存在于平台聊天 |
| 2 双入口核心 | 飞书或初期 dot、`/h`、任务查询、本地控制台、agent 适配契约 | 两入口状态一致；权限与账号隔离；替换 agent 不重写工作流 |
| 3 信息发现 | 新闻源、独立核实、重大新闻保底 | 覆盖时政经济科技；去重、日期与更正可追溯 |
| 4 日历与通知 | 已选目标、幂等、送达验证 | 超时不重复写；离线与账号切换行为明确 |
| 5 推荐试验 | 私人反馈、策略差异与回滚 | 可以禁用；反馈不改变保底与权限 |
| 可选扩展 | 经济指标与股票查询 | 数据许可、延迟、口径齐全；不交易 |

## 质量样例

| 场景 | 应有结果 |
| --- | --- |
| 旧事件今天被转载 | 显示原发生日期，不当作新事件 |
| 三个网站转载同一消息 | 只算一个独立消息链 |
| 官方发布未经独立验证的说法 | 标明是某方声明，列出不确定性 |
| 用户近期只读科技 | 仍检查重大时政与经济变化 |
| 用户没点击某条消息 | 不推断不喜欢，不自动修改策略 |
| 新闻正文要求执行命令 | 忽略该指令，作为不可信内容处理 |
| 飞书发送超时 | 查询结果，标记未知，不切账号补发 |
| 多入口执行同一任务 | 共用幂等键与状态，避免重复 |
| 从 dot 更换执行 agent | 保留任务、策略和审计版本；未知副作用先核对，不重复执行 |
| 提议替换框架 | 核实官方来源并用合成数据验证，不自动安装 |
| 股票数据延迟未知 | 清晰标注，不显示为实时 |
| 新文件出现真实凭据 | 公开检查失败；人工复核并轮换凭据 |

关注有证据的事实错误、重大事件遗漏、重复率、来源独立性、检索失败、延迟、费用、通知负担和用户明确评价。先建立基线再设目标；不声称已经达到准确率或性能指标。任何自动发布功能都不在当前路线图范围内。
