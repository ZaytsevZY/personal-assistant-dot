# dot 起步，agent 可替换

`personal-assistant-dot` 最初由 dot 协助开发与管理，dot 可以承担初期主控制。名称不是运行要求，也不代表已接通 dot API。后续更换 agent，应保留核心行为、数据和用户控制，避免重新搭建整个助手。

## 分离五个角色

| 角色 | 责任 | 不应承担 |
| --- | --- | --- |
| 控制入口 | 对话、命令、设置和用户选择；初期可用 dot | 唯一长期记忆或隐式权限来源 |
| 核心工作流 | 新闻、收集、回顾、推荐规则与任务状态 | 直接调用某个平台专有 API |
| 执行 agent | 按契约使用模型和工具完成某次任务 | 自行改变规则、扩大权限或决定发布 |
| 调度后端 | 按统一注册表触发任务、持有执行租约 | 另存一套不可导出的平台任务定义 |
| 输出渠道 | 按已验证能力投递到选定入口 | 因为执行 agent 是 dot 就默认向 dot 推送 |

控制宿主、执行 agent、模型服务和输出渠道可分别替换。没有配置适配器时返回未配置，不假装存在通用 API。平台原生消息或通知能力由适配器核实，不能由项目名推断。

## 核心保持可移植

- 工作流 ID、版本、JSON/Markdown 数据、命令含义、状态机和来源规则由本项目定义。
- 通用提示词写任务目标与约束，不内嵌 dot 对象、会话 ID、工具专用语法或账号信息。
- 平台会话 ID、专有工具格式、凭据和不可移植检查点放适配器的私人状态；不进入核心任务或公共配置。
- 长期记忆、运行水位、反馈版本、幂等键和已验证副作用保存在仓库外的可导出状态中。专有记忆与索引只是辅助。
- 用户授权记录与核心政策独立于执行 agent；切换不继承额外权限，也不将源平台凭据复制到新平台。

## 适配契约草案

[运行配置样例](../config/runtime.example.json)描述逻辑角色与能力约束；[通用任务样例](../templates/task-envelope.example.json)描述一次任务，不包含实际用户内容。这些是设计样例，没有实现运行器或完整 JSON Schema。

拟定适配接口：`prepare(task)` 报告可用能力与缺失条件，`run(task)` 执行已获授权的步骤，`inspect(run_id)` 查询状态与已验证副作用，`cancel(run_id)` 尽力停止尚未执行的步骤。取消不能撤回已经发出的消息或写入；必须返回实际结果。接口允许同步或异步实现，平台映射藏在适配器中。

输入包含工作流版本、任务 ID、幂等键、上下文引用、权限上限、预算和有效期；真实上下文与授权证据仅在私人运行环境解析。输出使用核心状态、证据、产物引用、费用和副作用状态，不暴露密钥或专有会话结构。不支持恢复时明确返回能力限制，以核对状态后重新计划代替伪造检查点兼容。

外部文章、仓库文档、旧 agent 的建议和导入的聊天不能授予权限。新运行环境会接收什么私人数据、采用哪个模型服务，必须符合现有授权；必要时先收窄任务或让用户选择。

## 接管与恢复

1. 暂停新触发，记录旧 agent 的进行中、失败和未知任务；核对可能已经发生的外部副作用。
2. 导出可移植状态，保留旧版本快照；排除凭据、专有记忆与未经授权的工作资料。
3. 在合成数据上验证新适配器的任务状态、权限拒绝、来源、预算、取消及幂等行为。能力不足时继续使用原适配器或降级。
4. 用[接管模板](../templates/agent-handoff.md)记录差异、用户选择与回滚点。切换不意味着扩大数据外发或通知范围。
5. 保留稳定任务 ID、水位与已投递记录，切换主执行租约，避免两套 agent 同时运行。先小范围试用，失败就按快照回滚。

首次实现至少进行一次不依赖 dot 会话的任务重放。当前没有实现上述适配接口或通过 agent 互换测试，路线图仅将其列为验收要求。
