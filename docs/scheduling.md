# 项目内统一调度

## 单一配置来源

调度定义统一维护在项目的注册表中，不分别在聊天应用、系统定时器和云平台手工设置互不关联的任务。[调度样例](../config/schedules.example.json)定义每日新闻与每周开源检查两个稳定任务 ID，初始均不启用。具体时刻、时区、目标账号、地址和密钥留在仓库外的私有覆盖配置中。

本地 MVP 的 `/schedule` 仅查看注册表；`/run` 只手动运行独立的合成演示工作流，不触发每日新闻或每周真实开源任务。只有每日新闻支持经私人配置显式启用本机时钟触发；其他任务不接后台执行。任何公开配置都不能开启投递。

当前已有[手动计划与账本](manual-plans.md)，由本注册表引用配置，支持 IANA 时区、错过策略、水位与显式合成运行。[交互工作台](local-console.md)可以预览、登记和手动运行合成候选，该候选账本不接后台触发。`/console` 的[兼容快照](console-snapshot.md)另有临时 UTC 演练，不修改实际计划。

未来调度器读取“公共默认配置 + 私有覆盖”，形成一个经校验的有效配置，并展示版本、变更、下次执行时间、运行位置与投递能力。一个任务同一时刻只允许一个主执行后端；采用租约或锁防止本地与常在线实例双跑。修改频率从同一控制入口写回配置，不另建一份独立平台任务。

任务通过稳定的工作流 ID 交给可替换的执行 agent，不在调度项中写死 dot 会话、平台定时任务 ID 或专有命令。dot 更换为其他 agent 时保留原任务 ID、运行水位和投递去重状态，迁移步骤见[agent 可替换设计](agent-portability.md)。

## 默认与启用条件

默认每日新闻、每周开源检查并整理建议，不指定虚构的具体时间。本机新闻存档启用前需要时区、时间、执行位置、失败策略和一次端到端验证。对外投递还需独立确认输出渠道、账号与会话。重大新闻即时推送是独立可选能力，不能由每日任务的存在推定已启用。

## 运行位置

| 后端方案 | 优点 | 限制 |
| --- | --- | --- |
| 本地 Mac | 私人数据接近本地、部署轻 | 休眠、关机、断网时无法保证执行或送达 |
| 常在线自托管服务或设备 | 不依赖用户打开电脑，可向手机渠道投递 | 运维、凭据、网络安全和费用需配置 |
| 经验证的托管调度服务 | 可承担公开信息检索 | 必须确认执行环境与渠道支持；不能默认访问本地文件 |

GitHub public 仓库不是私人数据运行环境。即使未来选择 Actions，也不能将本地私人目录、提示词输入、账号映射或敏感日志放进公共构建产物。执行后端和公共代码托管是两个独立选择；公开仓库不会代替部署本机后端。

## 渠道与手机可达性

输入入口与输出渠道分别配置。用户可以在飞书或 dot 对话，但不能因此假定 dot 是任意外部程序可调用的推送接口。对 dot 先核实当前产品支持的接入、后台任务、主动投递与移动端通知能力；没有官方可用接口时，不通过非正式方式模拟推送。

飞书也需要确认具体账号、应用能力、目标会话、权限和手机通知。公开样例不启用或指定投递渠道；实际渠道、账号与会话只在本机私人配置，只有验证投递链路后才标为“已启用”。

如部署了独立投递任务，本机收集与存档不等于发送。投递任务只使用符合当期条件、已写入并回读确认的本机记录；固定日期的每日和每周简报错过当期即跳过，不补发旧期。其他允许延迟的任务可独立定义队列、截止时间和重试策略。准备、平台接受、结果未知与用户实际收到是不同状态；按期记录，可参照[本机项目记录约定](privacy.md)，不要把未知结果当作失败自动重发。


## 每日新闻本机执行

真实每日新闻使用项目注册表中的 `daily-news`。公开配置不启用任何任务；仅在仓库外的私人根目录显式设置后，外部时钟才可触发：

```sh
python3 -B -m assistant_dot --private-root "<private-root>" /news-daily-config --enabled yes --timezone Etc/UTC --time 09:00
python3 -B -m assistant_dot --private-root "<private-root>" /news-daily-tick
```

以上时间是示例。用当前用户的 macOS LaunchAgent（不需要管理员权限）在登录时和固定间隔执行第二条命令，或由其他平台的本机时钟执行。使用绝对 Python 路径、工作目录及私人根目录；调度器只发出时钟信号，不另存账号、频道、工作流或用户时间。工作台是否打开不影响运行。Mac 休眠或关机期间不会运行；启动后只检查当天是否已到点，不追溯旧日。

工作台「每日新闻」读取最近一次本机存档，也可按「立即运行今日新闻」。同一天完成或部分成功后复用同一份存档；全部来源失败时保存失败记录，只能手动重试。并发触发由独立锁挡住，提交整份 JSON 之前的中断可在之后安全重试，不发送消息。用 `/news-daily-status` 检查配置和最近记录。用 `--enabled no` 停用自动触发，或卸载本机时钟任务；历史存档保留。仅存固定 RSS 的公开标题、链接、时间与来源状态，不保存正文，不代表经过独立事实核查。
